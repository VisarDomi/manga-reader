## What went wrong before: established facts and limits

The previous implementation used two Xcode targets and selected a provider from
Info.plist at runtime, silently defaulting to Asura. That did not implement the
user's requested provider-specific build pattern. However, both targets already
used the same Swift ReaderStore and web UI; it is inaccurate to say Scythe had
its own copied history implementation.

The new build removes the runtime provider fallback and makes selection explicit
and compiled. This removes an ambiguity around guest/host metadata, but no trace
proved that fallback actually fired in the failing Scythe session. The old Scythe
container already contained five reading-history entries before replacement,
so the evidence does not support a blanket claim that it never persisted history.
Separate container IDs are not proof that every framework cache is isolated, but
we have no evidence establishing LiveContainer cross-app state corruption.

Earlier UI tests seeded progress/history, and native Scythe checks concentrated
on parsing/backup conversion. They did not adequately cover a first read creating
history and then Home using it. Added the same empty-history → read → Home
partial/cover → resume browser case for both providers, plus native persistence
from an empty store for numeric and full-route chapter IDs. These pass, alongside
existing restore/cache/manual-PC tests, TypeScript and both actual iPhone builds.

There was no controlled A/B isolating one failure mechanism. Provider selection,
build provenance and the shared 100ms delay changed together. Report the workflow
and verification failures candidly, but do not claim a conclusively identified
single-line root cause or blame LC without evidence.

## Fresh-session operation

Read `apps/ios/DEVELOPMENT.md` for the builder and `apps/livecontainer/SETUP.md`
for importing. `build:ios` builds only; it does not install. Linux config is
`apps/ios/deploy.local.json`; Mac mirror stays `/Users/visar/Developer/asura-reader`.
Build products are now `build/<provider>/Release-iphoneos/<Product>.app`.
The historical Xcode project/directory name does not imply Asura-only code.

Before an LC import, open its own UI, then import the selected .app and choose
the existing app in the replacement prompt. URL dispatch alone is not installation
proof. The app-inspector helper matches the shared asura://app/ origin for either
guest: verify provider/content, not the diagnostic filename. In particular,
`.ios-debug/asura-builder-installed.jsonl` captured Scythe (63 cards), despite its
filename, and must not be used as proof of an Asura runtime inspection.
